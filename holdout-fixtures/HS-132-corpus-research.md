## Deliverable 2 — BACnet/IP Wire Structure (UDP/47808)

### <a name="port-caveat"></a>Port: UDP 47808 = 0xBAC0 ✅ (with caveat)

- **Verified:** The BACnet reference stack (SourceForge `bacnet-stack`) defines `BACNET_IP_PORT` default **47808 (0xBAC0)**; Wireshark's BACnet/IP dissector binds UDP 47808 by default; multiple vendor references (EMQX, Inductive Automation, Chipkin) state 47808/0xBAC0. ✅
- **Caveat (⚠️):** The task's specific citation "**ASHRAE 135-2016 Annex J §J.2.1**" is consistent with how Annex J (BACnet/IP) is structured, but ASHRAE 135 is a **paywalled** standard — I could not open the primary text to confirm the exact subsection label `J.2.1`. The port value itself is confirmed by numerous authoritative secondary + reference-implementation sources. Treat the *number* as ✅ and the *exact clause label* as ⚠️ unverified-against-primary.

### Layering

A BACnet/IP packet on UDP/47808 is: **BVLC → NPDU → APDU**.

```
[ IP ][ UDP dst=47808 ][ BVLC ][ NPDU ][ APDU ]
```

### BVLC (BACnet Virtual Link Control) header ✅

| Offset | Field | Size | Value | Meaning |
|--------|-------|------|-------|---------|
| 0 | BVLC-Type | 1 | **0x81** | BACnet/IP |
| 1 | BVLC-Function | 1 | e.g. 0x0A / 0x0B | see table below |
| 2–3 | BVLC-Length | 2 | big-endian | **total** length of the entire BVLL message, **including these 4 header octets** |

- BVLC-Length definition verified from the ASHRAE Annex J addendum PDF (bacnet.org, Add-1995-135a): *"the 2-octet BVLC Length field is the length, in octets, of the entire BVLL message, including the two octets of the length field itself, most significant octet first."* ✅

**BVLC function codes** (Annex J; commonly implemented):

| Code | Function |
|------|----------|
| 0x00 | BVLC-Result |
| 0x01 | Write-Broadcast-Distribution-Table |
| 0x04 | Forwarded-NPDU |
| 0x05 | Register-Foreign-Device |
| 0x0A | **Original-Unicast-NPDU** |
| 0x0B | **Original-Broadcast-NPDU** |

(0x0A / 0x0B verified across ASHRAE addendum + EMQX + ICS-fuzzing references. ✅)

### NPDU (Network PDU) — minimal form ✅

For a non-routed local packet, the NPDU is just two octets:

| Offset | Field | Value | Meaning |
|--------|-------|-------|---------|
| 0 | Version | **0x01** | BACnet network-layer protocol version (always 0x01) |
| 1 | NPCI Control | 0x00 | bit7=0 → APDU (not a network-layer message); no DNET/SNET; normal priority |

- Control-octet bit 7 = 1 indicates a network-layer message; = 0 indicates the NSDU carries an APDU. ✅ (verified from BACnet packet-structure references). Full bit breakdown (bit5=dest present, bit4=src present, bit2=expecting-reply, bits1-0=priority) is standard practice. ⚠️ (bit-level detail inferred from common references, not primary text)
- A **global-broadcast** NPDU (typical for broadcast I-Am) uses control `0x20` + DNET `FF FF` + DLEN `00` + Hop-Count `FF`, i.e. `01 20 FF FF 00 FF`. ⚠️ common practice.

### APDU — Unconfirmed-Request (Who-Is / I-Am) ✅

| Offset | Field | Value | Meaning |
|--------|-------|-------|---------|
| 0 | PDU Type / flags | **0x10** | Unconfirmed-Request-PDU (type nibble = 1), unsegmented |
| 1 | Service Choice | Who-Is = **0x08**, I-Am = **0x00** | BACnetUnconfirmedServiceChoice |

- Service choice values (Who-Is = 8, I-Am = 0) verified. ✅
- **Who-Is** parameters are all optional → a bare broadcast Who-Is has **no** APDU payload after the 2-octet header. ✅
- **I-Am** parameters (per ASHRAE 135 **Clause 21** ASN.1) are a `SEQUENCE` with **no `[n]` brackets**, therefore encoded with **APPLICATION tags**, not context tags: ✅

  ```asn1
  I-Am-Request ::= SEQUENCE {
      iAmDeviceIdentifier     BACnetObjectIdentifier,  -- application tag 12 → 0xC4
      maxAPDULengthAccepted   Unsigned,                -- application tag 2  → 0x21/0x22
      segmentationSupported   BACnetSegmentation,      -- application tag 9  → 0x91 (enumerated)
      vendorID                Unsigned16               -- application tag 2  → 0x21/0x22
  }
  ```

> **Correction / pitfall flagged:** an initial deep-research pass encoded the I-Am parameters with *context-specific* tags (0x14/0x2A/0x39/0x4A). That is **incorrect** — I-Am-Request has no bracket numbers in its ASN.1, so the fields use application tags (0xC4/0x22/0x91/0x21). Verified against the BACnet.org Encoding guide (Clause 20.2 refs), bacnet-experts MS/TP encoding paper, node-bacstack `encodeApplicationObjectId/Unsigned/Enumerated`, and Wireshark decoding. ✅

### Minimal valid Who-Is packet (BACnet/IP, broadcast) ✅

```
81 0B 00 08 01 00 10 08
```

| Bytes | Layer | Meaning |
|-------|-------|---------|
| `81` | BVLC | BACnet/IP |
| `0B` | BVLC | Original-Broadcast-NPDU |
| `00 08` | BVLC | length = 8 octets (whole message) |
| `01` | NPDU | version 1 |
| `00` | NPDU | control: APDU, no routing, normal priority |
| `10` | APDU | Unconfirmed-Request |
| `08` | APDU | service choice = Who-Is (no params → "who is anybody") |

Wireshark decodes this as BVLC Original-Broadcast-NPDU → Unconfirmed-Request → Who-Is. ✅

### Minimal valid I-Am packet (unicast) ✅ — CORRECTED encoding

Example device: Device object instance **12345**, Max-APDU **480**, Segmentation **none (enum 3)**, Vendor-ID **24**.

```
81 0A 00 14 01 00 10 00 C4 02 00 30 39 22 01 E0 91 03 21 18
```

| Bytes | Layer | Meaning |
|-------|-------|---------|
| `81` | BVLC | BACnet/IP |
| `0A` | BVLC | Original-Unicast-NPDU |
| `00 14` | BVLC | length = 20 octets |
| `01 00` | NPDU | version 1, control 0x00 |
| `10 00` | APDU | Unconfirmed-Request, service choice = I-Am (0) |
| `C4 02 00 30 39` | APDU | app tag 12 (Object Identifier), len 4: Device (type 8) instance 12345 → 0x02003039 |
| `22 01 E0` | APDU | app tag 2 (Unsigned), len 2: Max-APDU-Length-Accepted = 480 |
| `91 03` | APDU | app tag 9 (Enumerated), len 1: Segmentation-Supported = 3 (no-segmentation) |
| `21 18` | APDU | app tag 2 (Unsigned), len 1: Vendor-ID = 24 |

- Object-ID packing: `(object_type << 22) | instance` = `(8 << 22) | 12345` = `0x02003039`. ✅
- BACnetSegmentation enum: `segmented-both(0)`, `segmented-transmit(1)`, `segmented-receive(2)`, `no-segmentation(3)`. ✅
- **Broadcast I-Am variant** (more realistic, since I-Am is usually broadcast): replace BVLC function with `0B`, use global-broadcast NPDU `01 20 FF FF 00 FF`, and recompute length to `0x0018` (24):
  ```
  81 0B 00 18 01 20 FF FF 00 FF 10 00 C4 02 00 30 39 22 01 E0 91 03 21 18
  ```
  ⚠️ NPDU global-broadcast fields are common-practice; a bare `01 00` NPDU with function `0B` is also dissected correctly by Wireshark.

### For HS-132 (undissected-protocol detection)

To validate that the passive analyzer **flags BACnet/IP as an undissected protocol**, the fixture only needs UDP datagrams to/from port **47808** whose payload starts with **`0x81`** (BVLC type) — the analyzer should recognize the port + BVLC signature and report the protocol as present-but-undissected.
